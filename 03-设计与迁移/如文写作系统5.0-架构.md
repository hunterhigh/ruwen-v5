# 如文写作系统5.0架构

## 1. 这次解决的四个问题

### 作用域不再只是编号

每项资料同时声明职责、状态、适用项目/卷/故事弧/章节/场景类型/POV、读取岗位和是否允许进入小说作者。作用域由注册表与编译器执行：失效、未批准、哈希改变、越权或不匹配的资源不能被装入作者资料包。

职责同时受目录和注册类型约束，不能靠修改type把`研究/`材料伪装成世界或故事输入。资源激活、岗位交接、候选批准与记忆提交使用绑定目标哈希的独立批准事件；每个事件通过独占创建的消费标记取得一次性执行权，未完成的业务提交会回滚临时标记。

### 领域研究不再直接变成领域写法

现实知识与文学样本先由外部知识顾问进入`研究/`，再由项目治理员决定其属于人物、世界或表现。只有表现设计师产出的来源无关候选能进入`表现/`，且须通过闭合审计和非正典试写。

### 项目初始化形成可承接的画布

主角档案不是人物标签集合，而是客观存在、内在组织、叙述接口三种互相解释的模型。世界资料不是可选百科文章，而是世界总表、当前态势和具有统一关系结构的系统。正式章节生产前，人物、世界和项目声音必须达到最小就绪状态。

### 世界观有激活与转译协议

世界全文不交给小说作者。章节情境编译员从主角当前状态和故事压力出发，选择会改变动作、成本、感知/误认、社会含义或世界自身运动的条件。这样既保留防倾倒隔离，也减少逻辑正确却像通用布景的结果。

## 2. 生产链

`用户表达 → 创意协调员 → 项目治理/外部顾问/表现设计/故事构思 → 章节情境编译 → 小说作者 → 情感读者 → 文学编辑 → 两类核验 → 用户批准 → 记忆维护`

系统仍只有两个用户入口。内部岗位是权限隔离边界，不是用户要逐项操作的流程页面。

## 3. 信息为什么被拆开

- `人物`负责人物存在和经验世界的方式；
- `世界`负责现实自身怎样运行；
- `故事`负责未来可能和批准剧情；
- `表现`负责小说作者可以直接调用的项目文字能力；
- `校验`只在写后拒绝硬错误；
- `研究`保存证据和文本观察；
- `治理`保存权属、作用域、版本和审批。

同一信息只允许一个权威所有者。下游通过资源ID和干净交接物取得所需部分，不复制解释。

## 4. 防止文学转译变成履约写作

创意协调员把人的表达拆成固定事实、创意价值、共存而未决的力量、开放实现、归属与作用域，并剥离例子、抱怨和完整路线。表现设计师只描述文字决定之间的关系。

表现资源的六项审计分别检查：完整路线、逐项履约、封闭映射、例子锚定、过高语义密度、来源表面靠近。任何未解决风险都会阻止资源从`proposed`进入`candidate`。

## 5. 小说作者的实际权限

小说作者只看到项目声音、当前POV镜头、必要关系镜头、最多一项当前表现能力、generation field、最近批准正文尾部和明确逐字文本。总预算仍为8,000字符。

小说作者不读取人物档案、世界资料、故事大纲、研究、治理、校验和文学问题账本。来源丰富度由上游选择质量承担，不以整库倾倒换取。

## 6. 常态治理

初始化、研究导入、表现资源变化、新卷/新弧、弧线退役、章节情境编译前、记忆更新后和弧线结束都会触发治理检查。注册表检查唯一所有者、哈希、状态和作用域；编译器再次检查作者读取权限；审计账本只保存技术事件。

文学问题账本与治理账本分开。治理层只能看到类别和复发统计；单次投诉不会变成作者禁令，长期复发也必须重新经过表现设计和试写。

## 7. 候选版没有宣称的事情

5.0已经把文档职责、作用域、权限和闭合风险变成可执行结构，但尚未证明任何新项目声音或领域能力能稳定提高文学质量。只有行为验证得到用户确认后，候选系统及具体表现资源才可升级。
