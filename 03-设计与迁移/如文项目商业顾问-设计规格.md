# 如文项目商业顾问设计规格

日期：2026-08-29
状态：设计已确认，尚未实施

## 1. 设计结论

建设一个独立于 Ruwen 写作本体的通用项目商业顾问。它把作品视为需要投入时间、资金与注意力的经营项目，在立项前形成商业判断，在上线后使用真实数据检验和修正该判断，最终帮助用户决定立项、继续、调整、追加投入、降低投入、暂停或停止。

商业顾问不评价章节读起来是否具有商业吸引力，不承担文本编辑，也不进入逐章生产流程。文本商业判断、体裁编辑、叙事补全和中文本地化属于其他能力。

首个市场试点为起点。起点只是可替换的平台资料来源，不改变商业顾问的通用决策结构。

## 2. 核心决策问题

商业顾问只为具体经营决策工作：

- 这个项目是否值得立项；
- 应选择怎样的市场、平台、受众或商业模式；
- 项目的商业判断依赖哪些事实和假设；
- 现实投入是否与潜在回报相称；
- 上线后的实际结果是否支持原判断；
- 应继续、调整、追加投入、降低投入、暂停还是停止。

没有待作出的决策时，顾问不得为了展示完整性而生成泛化市场报告。

## 3. 能力边界

### 3.1 负责

- 把用户的担忧转化为可调查、可证伪的商业问题；
- 按需研究平台、市场、竞品和商业模式；
- 在每次咨询时核验与当前问题有关的规则和数据口径；
- 使用公开数据、用户提供的私有数据和明确标注的模型参数；
- 计算章节数、字数、单章长度、更新频率、票数变化、订阅、收入、成本和利润等与当前决策有关的数值；
- 区分事实、派生计算、解释、假设和情景估算；
- 比较可选行动的收益、成本、风险和可逆性；
- 保持立项假设与上线结果之间的连续性；
- 输出经营建议及能够改变建议的后续证据。

### 3.2 不负责

- 阅读样式章并判断文字是否“有商业感”；
- 评价或改写单章、开篇、大纲和人物；
- 承担体裁编辑、叙事补全或中文本地化；
- 自动改变 Ruwen 的项目设定、故事或正文；
- 输出固定分析维度、固定评分或统一成功模板；
- 运行定时任务、持续爬取平台或建设全站历史数据库；
- 自动登录作者后台、保存账号凭证或访问未授权接口；
- 把公开代理指标冒充订阅、收入、留存或因果证据。

## 4. 最小决策过程

商业顾问只有三个稳定阶段。具体研究内容和回答形式由问题决定，不把阶段展开成固定报告栏目。

### 4.1 明确决策

确定本次要决定什么、项目处于什么经营阶段、面向哪个市场、用户可支配哪些资源，以及哪些创作价值或现实约束不可牺牲。

### 4.2 建立或检验商业判断

立项前，顾问根据外部市场证据、项目构想和资源条件形成可验证的商业判断。上线后，顾问把真实经营结果与原判断比较，识别哪些事实成立、哪些假设被削弱、哪些变量仍然未知。

当需要外部信息时，先核验与问题直接相关的平台规则和指标定义，再采集最小必要样本。不得因为已有旧资料而默认口径仍然有效。

### 4.3 提出经营行动

顾问根据证据提出立项、继续、调整、追加投入、降低投入、暂停或停止等行动建议，并说明理由、替代方案、成本、风险、预期观察结果和会改变结论的新证据。所有行动由用户决定。

## 5. 立项与上线后的连续关系

立项分析和上线经营分析属于同一能力，因为后者用于检验前者：

```text
市场证据与项目条件
→ 形成商业判断和可验证假设
→ 用户决定是否投入
→ 项目上线并产生真实结果
→ 实际结果与原判断比较
→ 修正假设和经营策略
→ 用户决定继续、调整或停止
```

立项前的结论不得写成确定预测。上线后也不得只描述指标变化，而应回到原商业判断，解释变化是否真正影响当前经营决策。

## 6. 数据与证据

### 6.1 数据类别

- 公开事实：平台规则、作品页面、榜单和平台公开说明；
- 公开观察：指定时间观察到的月票、推荐票、字数、章节数、更新时间、排名等；
- 私有事实：用户主动提供的作者后台订阅、阅读、收入、结算和运营数据；
- 派生计算：平均章节字数、更新间隔、变化率、收入成本和利润等；
- 模型参数：未知付费人数、分成、税费、成本或其他用于情景估算的变量；
- 商业解释：对数据关系的解释及尚未验证的因果假设。

月票、推荐票和排名是公开代理信号，不等于订阅、留存或收入。私有数据缺失时，相关结论必须保持未知或作为区间模型，不得用代理信号补成确定数值。

### 6.2 查询时更新

系统不定时采集数据。每次用户咨询时只做与当前决策有关的更新：

1. 核验相关平台规则、指标定义和时间范围；
2. 检查活动期、双倍期或其他会改变口径的事件；
3. 获取能够回答问题的最小公开样本；
4. 接收用户愿意提供的项目私有数据；
5. 完成计算并记录来源时间与限制。

### 6.3 数据质量不变量

- 缺失值不是零；
- 不同统计周期的数据不得直接比较；
- 规则或指标定义变化前后的数据必须分开解释；
- 样本选择条件必须与结论范围一致；
- 相关性不自动构成因果关系；
- 事实、推断和估算必须能被读者区分；
- 关键来源无法确认时，降低结论强度或停止判断。

## 7. 收入与利润

能够取得后台结算数据时，优先使用实际收入：

```text
现金收入
= 订阅结算 + 奖励与其他收入 - 税费与渠道扣减
```

无法取得实际收入时，只能建立情景模型：

```text
估算订阅收入
= 付费字数 ÷ 1000
× 假设平均付费人数
× 千字价格
× 假设作者分成比例
```

情景模型至少说明参数来源和合理范围，不把结果称为实际收入。

需要判断项目投入价值时，另计算经济利润：

```text
经济利润
= 现金收入
- 工具成本
- 编辑或外包成本
- 投放成本
- 作者时间机会成本
```

未知参数保留为变量或区间，不制造虚假精确度。

## 8. 平台资料

平台资料只保存可以帮助查询时重新核验的轻量信息：

- 平台身份和适用市场；
- 官方规则与常用权威来源入口；
- 可观察的公开字段；
- 私有后台可能提供的数据类别；
- 收入计算口径；
- 已知代理指标和误判风险；
- 最近一次核验时间。

首版只提供起点资料。平台资料不是永久真理，最近核验时间只表示上次检查，不表示当前仍然有效。

## 9. 轻量项目商业状态

每个正式项目只需要一个可选的 `项目/商业状态.md`，用于保持商业判断的连续性。它不是数据库，也不是分析报告仓库，只记录：

- 当前经营决策；
- 仍然有效的关键商业假设；
- 已被数据削弱或否定的假设；
- 用户批准的投入与风险边界；
- 当前需要验证的问题；
- 最近一次决策日期。

具体调查材料在确有复核价值时保存于 `研究/商业化/`。不要求保存全量网页、长期榜单快照或作者后台原始文件。私有原始数据是否保留，由用户逐次决定。

## 10. 与 Ruwen 的接口

通用商业顾问不进入 Ruwen 的两个现有写作入口，也不成为逐章生产链的一部分。双方只有两个连接点。

### 10.1 立项交接

```text
商业顾问形成项目立项意见
→ 用户批准其中的项目定位和商业条件
→ Ruwen constructor 接收已批准结论
```

交接物只包含用户批准的目标平台、目标受众、项目机会、投入边界、需要验证的关键假设和不可牺牲的创作价值。市场研究原文、竞品材料和顾问推理不直接进入创作上下文。

### 10.2 经营调整交接

```text
商业顾问根据上线结果提出经营建议
→ 用户决定是否调整项目
→ 批准的变化交给拥有相应职责的 Ruwen 模块
```

商业顾问只描述要解决的经营问题、依据和预期结果，不规定具体剧情、句子或编辑手法。

## 11. 与文本商业判断的关系

文本商业判断是独立能力。它以章节或作品文本为对象，研究读者是否容易理解、继续阅读或获得预期体验。商业顾问以项目经营决策为对象，不亲自承担这种阅读判断。

当经营数据提示可能存在文本问题时，商业顾问可以提出调查问题；文本能力完成诊断后，其结论可以作为商业顾问的一项证据。样式章只适用于测试文本能力，不用于验证商业顾问。

## 12. 技术形态与方案选择

设计比较过三种形态：

1. **直接扩展 Ruwen 本体**：调用路径最短，但会把通用商业分析耦合到小说写作流程，并诱发章节级商业审核，因此不采用。
2. **通用商业顾问技能加 Ruwen 薄交接**：既能连接立项与上线结果，又不污染写作上下文；平台资料可以替换，首版维护成本最低，因此采用。
3. **独立研究系统或多 Agent 商业部门**：能容纳更大数据量和专业分工，但需要数据库、调度、接口和额外治理，早期没有足够收益证明其成本，因此不采用。

所选方案的主要代价是查询时可能重复调查，且分析速度依赖当时可访问的数据；这是接受的取舍，因为当前优先目标是验证商业顾问能否改善项目决策，而不是建设市场基础设施。

推荐形态为一个可复用的独立商业顾问技能，以及 Ruwen 内部的最薄交接约定：

```text
通用项目商业顾问
├── 决策定义
├── 按需市场研究
├── 数据与利润计算
├── 商业假设检验
└── 经营建议

Ruwen
├── 可选的项目商业状态
└── 两类批准后交接
```

商业顾问的逻辑不依赖 Ruwen 目录结构；Ruwen 只规定如何接收批准结论和隔离研究材料。更换平台或把顾问用于其他类型项目时，不需要复制一套新的决策流程。

## 13. 首版范围

首版实现：

- 通用项目商业顾问入口；
- 三阶段决策过程；
- 起点轻量平台资料；
- 查询时的规则和数据口径核验；
- 公开数据与用户私有数据输入；
- 必要的派生数值及利润情景计算；
- 可选的项目商业状态；
- 立项与经营调整两类 Ruwen 交接。

首版不实现：

- 定时任务、全站采集和长期市场数据库；
- 仪表盘、固定评分或成功率预测；
- 自动登录和未授权数据访问；
- 样式章评价、文本编辑和逐章商业审核；
- 起点之外的平台资料；
- 多 Agent 商业部门。

## 14. 验证方案

验证使用同一个模拟项目的两个阶段，不使用样式章。

### 14.1 立项测试

向顾问提供项目构想、目标市场和资源约束，检查它是否：

- 明确当前待作出的经营决策；
- 按需核验起点规则和市场证据；
- 使用数字时说明口径、时间和来源；
- 区分事实、假设和情景估算；
- 给出可执行的立项意见和验证条件；
- 不评价不存在的章节文本。

### 14.2 上线后测试

向同一项目补充模拟或真实经营数据，检查它是否：

- 找回并检验原商业假设；
- 区分公开代理信号与后台实际结果；
- 计算必要的收入、成本或变化指标；
- 根据证据修正原判断；
- 给出继续、调整、降低投入或停止等经营建议；
- 不越权提出具体文本改写。

### 14.3 验收标准

首版通过的必要条件是：

1. 同一商业判断能从立项延续到上线后验证；
2. 分析内容由当前决策和可用证据决定，不套固定维度；
3. 规则和数据只在咨询时按需更新；
4. 数字、来源、口径和不确定性可复核；
5. 无后台数据时不伪造订阅、收入或利润；
6. 商业顾问与文本判断、编辑和小说作者保持职责隔离；
7. 用户保有所有立项、投入、调整和停止决定。

## 15. 后续扩展条件

只有首版证明商业顾问能改善真实项目决策后，才考虑：

- 增加其他平台资料；
- 增加经过授权的数据导入适配器；
- 沉淀跨项目案例，但仍避免把短期相关性固化为规则；
- 将文本商业判断作为独立能力接入；
- 在明确维护收益后增加更自动化的数据处理。

任何扩展都不得改变本设计的核心边界：商业顾问负责项目商业决策，文本能力负责文本判断，用户负责最终选择。
