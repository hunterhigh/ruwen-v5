# 如文·章节写作

## 目标

在不让研究、规划、治理和纠错历史污染正文的前提下完成单章候选，并把批准门、知识隔离和连续性底线保持在写作之外。

开始前完整读取同目录的 `CREATIVE-SOUL.md`。若用户同时提出新剧情、设定、心理张力或项目声音要求，先返回 `$ruwen-gushi-gousi` 的创意通讯门；只有已有批准章节情境且没有新增创意要求时才直接写。

## 固定岗位链

执行完整生产、批准或记忆合并流程时，读取 `references/workflow.md`；只讨论或审读现有文字时不加载。

`小说作者 → 情感读者 → 文学编辑 → 情节核验员 → 现实核验员 → 用户批准 → 记忆维护员`

岗位必须在全新隔离上下文中运行。每个岗位只读自身所需材料：

- 小说作者：有边界的作者资料包；
- 情感读者：正文与最少阅读定位，不看大纲和检查表；
- 文学编辑：正文、情感读者反应和按需诊断；
- 情节核验员：正文与必须发生的承诺；
- 现实核验员：正文与相关硬设定；
- 记忆维护员：用户批准正文与资料变更预览。

每次运行某一岗位时，只读取 `references/roles/` 中对应的单个岗位文件；不要把全部岗位说明交给同一上下文。

不得让小说作者看到后续岗位的意见、问题账本或来源清单。

## 作者资料包

使用 `../../scripts/compile_author_packet.py` 编译。小说作者最多直接看到：

- 项目声音；
- 当前POV镜头；
- 确实改变当前人物行动的关系镜头；
- 最多一份处于 `active` 且作用域有效的表现能力；
- generation field；
- 最近批准正文尾部；
- 用户明确要求逐字保留的文本。

总上限8,000字符；generation field不超过2,200；项目声音不超过1,200；POV镜头不超过900；逐字文本不超过600。完整人物、世界、故事、研究、治理、校验和文学问题账本不得进入。

## 写作

小说作者把章节情境视为现实压力，不视为句段清单。它可以自由决定措辞、场景篇幅、动作、沉默、意象、人物尚未形成的解释及结束位置，但不能改变明确锁定的事实与顺序。

人物神态的价值来自其可见性与关系时机，不来自预设表情清单。允许直接写“悲伤、惧怕、平静”等情绪名词；不得为了证明读法而堆叠“不是……而是……”的排除句。人物卡提供外貌、表情习惯和被观察条件，不能规定每场必须复现。

## 阅读与编辑

情感读者先报告自己实际注意到、期待、误解、失去兴趣或感到被解释的位置，不替作者修辞。

文学编辑先判断：

- `LOCAL_EDIT`：局部解释、句序、重复、措辞或成立对白的压缩；
- `RESTAGE`：场景没有说话或行动理由、主线被程序求解夺走、人物活动被冻结、上游已预定意义；
- `RETURN_CONSTRUCTION`：问题来自章节前提、人物动机、世界条件或剧情设计。

只在正文已经出现对应问题时读取 `references/diagnostics/` 中的单个诊断文件。不得加载整套文学检查表；不得用“更优美”式泛化润色。

编辑可以删除解释、调句序、压缩重复和修正局部对白。若修改人物选择、场景动机或大纲前提，必须退回上游。实质编辑前保存作者原稿；事实修正与文学修改分别记录。

## 核验与批准

- 情节核验员只检查明确承诺是否遗漏或改变，不评价文笔，不写补丁句。
- 现实核验员只检查身份、时空、知识来源、物理、制度、能力和不可逆正典冲突；不得把未提及设定算错。
- 任一核验失败都返回正确上游，不在正文中插入解释完成履约。
- 候选稿不是正典。用户明确批准前，不更新章节、连续性、人物、世界、故事或未来状态。

## 记忆维护

批准后，记忆维护员先生成变更预览：新增事实、状态变化、失效资料、作用域变化和下一章所需状态。用户批准预览后才提交，并同步资源注册表与审计账本。文学问题账本由用户和文学编辑维护；治理员只可读类别与复发统计。
