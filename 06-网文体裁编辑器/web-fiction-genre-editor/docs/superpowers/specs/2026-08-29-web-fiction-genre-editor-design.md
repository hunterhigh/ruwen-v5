# 网文体裁编辑器设计

日期：2026-08-29  
状态：用户已确认

## 1. 结论

建设一个与 Ruwen 独立的轻量网文体裁编辑器。它不是 Ruwen 的第三个入口，不加入章节生产岗位链，也不改变 Author 的写作上下文。

用户在需要时单独调用编辑器，把 Author 已经完成、但尚未获得用户批准的初稿交给它。编辑器直接对这份候选正文进行补充、扩写、拼接和重写。修改后的正文仍是批准前候选稿；它沿用原项目已有的用户批准机制进入正典。编辑器本身不写正典、不更新项目记忆。

## 2. 职责

编辑器负责把已经成立的章节写得更符合连载网文的阅读方式，尤其处理：

- 读者看见了事件，却还不能充分理解其特殊性、价值或后果；
- 动机、关系、场景或胜负已经存在，但在正文中重量不足；
- 必要的知识、往事、生活经验或世界信息尚未参与当前剧情；
- 功能性补写与原文之间存在接缝，需要连同入口和回流一起重写；
- 新增内容需要服从项目声音，并在扩写后接受文学压缩。

它可以大幅修改候选正文，但不能擅自改变明确锁定的事件、人物选择、世界规则和结果。若增强章节必须改变这些上游条件，编辑器停止补写并指出需要返回构思的问题。

## 3. 网文编辑原则

网文不仅让事情发生，也主动组织读者怎样理解、估值、预期和回味事情。说明、评论、回忆和旁观判断可以占据正文，但必须参与当前事件。

编辑不使用“世界观、人物动机、伏笔”等固定缺口表。它从成稿中的具体事件出发，判断哪部分阅读效果尚未成立，再决定是否扩写。

扩写的基本单位不是插入段，而是重织：

1. 找到当前事件中的触发物；
2. 判断读者尚未获得的理解、估值、情绪或后果；
3. 选择符合本书声音的承载方式；
4. 写出本身具有叙事性的补充内容；
5. 同时改写前文入口和后文回流；
6. 检查新增内容是否真正改变了读者对当前剧情的阅读。

可用的承载方式包括叙述判断、人物推断、回忆、传闻、旁观者、对话、资料、习俗和事后处置，但没有任何一种是必选手法。解释可以直白，也可以走远；只要仍被当前欲望、危险、关系或胜负牵引。

文学整合与功能拼接不被视为二选一。编辑器允许按功能生成材料，再通过声音、视角、入口和回流把接缝重写进作品。完成深度补写后，可以继续由原项目的文学编辑处理重复、句序和节奏压缩。

## 4. 输入上下文

编辑器按需读取：

- Author 的批准前初稿；
- 相邻已批准正文的必要片段；
- 当前项目声音；
- 当前章节明确锁定的事件与结果；
- 与实际改写位置有关的人物、关系和世界事实；
- 用户本次提出的编辑目标。

编辑器不需要 Author 的隐藏推演，不读取用户投诉与纠错历史作为写作材料，不自动加载完整世界百科、研究原文、未来剧情答案或无关治理资料。

## 5. 输出与批准

编辑前保存 Author 原稿。主要输出只有：

1. 直接修改后的完整候选正文；
2. 一份简短的改动说明，标明深度补写位置和是否触及上游边界。

编辑器不建立第二套批准流程。修改后的候选稿回到原项目已有的批准环节；只有用户明确批准后，项目原有机制才能把它提升为正典并更新记忆。

## 6. 与 Ruwen 的关系

```text
Ruwen Author 产生批准前初稿
        ↓ 用户单独调用
网文体裁编辑器直接修改候选稿
        ↓
原项目的阅读、核验或用户审阅
        ↓ 用户明确批准
原项目机制写入正典
```

Ruwen 不依赖本编辑器，编辑器也不调用 Ruwen 的运行代码。未调用编辑器时，Ruwen 的生产流程完全不变。

## 7. 防止过度拟合

《问锋台》中拳法、台沿、烧窑和阴寒等具体内容不进入编辑器规则。它们只用于验证编辑器能否从当前事件出发完成估值、扩写、回流和压缩。

至少使用以下不同场景验证：

- 战斗章节：能解释胜负特殊性，但不要求每个动作都附带说明；
- 关系章节：能加强关系代价和情绪回报，不套用战斗结构；
- 已经充分成立的章节：能够不做无意义扩写；
- 需要改变正典前提的请求：能够停止并返回上游，而不是编造设定。

## 8. 首版结构

首版只包含一个插件、一个技能入口和少量参考文件：

```text
web-fiction-genre-editor/
├── .codex-plugin/plugin.json
├── README.md
├── skills/web-fiction-genre-editor/
│   ├── SKILL.md
│   └── references/
│       ├── editing-method.md
│       └── context-and-approval.md
└── validation/
```

不实现多 Agent 编排、能力包系统、项目配置引擎、自动正典写入、数据库或 Ruwen 工作流接入。
