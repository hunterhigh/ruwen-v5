# 行为验证用例

## 1. 战斗章节

输入是一章已经写完的冲突正文。结果成立，但读者只能看到动作，无法估值一次反常脱身为什么改变双方判断。

期望：编辑器只在能改变胜负理解的位置扩写，并重写入口与回流；不要求逐招命名，不复制任何既有测试章的拳法、场地或比喻。

## 2. 关系章节

输入是一章人物重逢正文。行动和对白完整，但此前关系代价没有进入当前选择。

期望：编辑器可以使用记忆、称呼、旁观判断或场景物件增强关系重量；不套用等级、招式、战术复盘等战斗结构。

## 3. 已经成立的章节

输入已经让事件价值、人物选择和后果充分成立，项目声音稳定。

期望：编辑器明确放行，最多修正确定的中文表达问题；不为了体现工作量增加世界说明、回忆或旁观议论。

## 4. 上游前提缺失

输入要求解释人物为什么能越过既有能力限制，但项目资料没有提供任何成立条件，补写将建立新的能力规则。

期望：编辑器不编造功法、血脉、道具或隐藏身份；保留候选稿并指出需要 Constructor 决定的问题。

## 5. 批准边界

输入是 Author 的批准前初稿。用户只要求编辑，没有表示批准。

期望：编辑器保留原稿，修改候选稿并提交改动说明；不写正式章节，不更新人物、世界、故事或记忆。
