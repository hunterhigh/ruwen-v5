# 证据与模型规则

## 用途

在使用市场数据、项目经营数据、收入或成本模型时读取。这里规定证据边界和可复现计算，不规定回答必须使用哪些栏目。

## 证据性质

- **公开事实**：平台发布的规则、帮助说明和正式公告。记录来源、核验时间、适用范围与生效状态。
- **公开观察**：某个时间从公开页面观察到的数值或状态，例如字数、章节数、更新时间、月票、推荐票和排名。
- **私有事实**：用户主动提供并授权使用的作者后台、结算或经营数据。
- **派生计算**：从已知输入计算的平均章节字符数、更新间隔、变化率、现金收入或利润。
- **模型参数**：尚未确认的付费人数、分成、税费、成本或其他情景变量。
- **商业解释**：对证据关系的解释，包括尚未验证的因果假设。

引用数值时至少标明统计对象、时间范围、单位和来源性质。事实、计算、解释、假设和估算必须能被用户区分，但无需套固定报告格式。

## 数据质量不变量

- 缺失值不是零；不要擅自插补。
- 公开代理指标不等于后台经营结果。月票、推荐票和排名不能替代订阅、留存或收入。
- 不同统计周期、作品阶段、平台口径或活动条件的数据不得直接比较。
- 平台定义变化前后的数据分开解释。
- 样本选择条件必须与结论范围一致；方便取得的作品不是总体随机样本。
- 相关性不构成因果。事件前后变化也可能来自平台流量、活动、更新量或其他同时变化的条件。
- 数据过期、关键来源不可访问或口径不明时，降低结论强度或停止判断。
- 用户提供的私有数据只用于当前授权目的，不复述不必要的账号或读者个人信息。

## 立项与上线的证据关系

立项前的商业判断由事实和待验证假设组成，不是成功预测。记录最少的可证伪关系：

```text
若项目条件与市场机制成立
→ 预期出现某个可观察结果
→ 在约定资源和时间范围内检验
→ 结果支持、削弱或否定原判断
```

上线后优先检验原判断。不要看到一组新数据就另造一套与立项无关的分析。

## 收入和利润

后台结算完整时，现金收入为：

```text
现金收入 = 收入项目合计 - 扣减项目合计
```

无法取得实际订阅结算时，只能建立明确命名的情景：

```text
情景订阅收入
= 付费字数 ÷ 1000
× 假设平均付费人数
× 每千字价格
× 假设作者分成比例
```

项目投入判断需要经济利润时：

```text
经济利润
= 现金收入
- 工具成本
- 编辑或外包成本
- 投放成本
- 作者时间机会成本
- 其他明确成本
```

若结算项目不完整，只报告已知现金小计，不称为现金收入。若成本不完整，只报告已知成本，不给出经济利润。未知参数保持未知或进入保守、基准、乐观等由输入明确指定的情景，不暗中替用户设值。

## 确定性计算器

章节数据：

```powershell
python scripts/commercial_metrics.py chapters --input chapters.json
```

输入示例：

```json
{
  "source_timezone": "Asia/Shanghai",
  "chapters": [
    {
      "id": "001",
      "published_at": "2026-08-01T08:00:00+08:00",
      "chars": 2500,
      "access": "free"
    }
  ]
}
```

利润数据：

```powershell
python scripts/commercial_metrics.py profit --input profit.json
```

实际模式使用收入、扣减和成本项目，并由 `settlement_complete` 与 `costs_complete` 声明完整性。情景模式由用户逐个提供付费字数、假设付费人数、每千字价格、作者分成、额外收入、扣减和成本。计算器只计算，不解释，也不保存输入。
