# 如文项目商业顾问实施计划

日期：2026-08-29
状态：待用户批准实施
依据：`03-设计与迁移/如文项目商业顾问-设计规格.md`

## 1. 实施结论

实施拆成两个可以独立复制、测试、提交和验收的子项目，禁止在同一实施阶段跨仓库混改：

1. 先新建独立的通用项目商业顾问仓库，完成技能、起点资料、确定性计算和行为验证；
2. 独立技能通过用户验证后，再单独修改 `v5ruwen`，加入可选的项目商业状态模板和最薄治理连接。

第一阶段不修改 Ruwen。第二阶段不复制商业顾问的推理、平台资料或计算代码。两个项目之间不存在运行时代码依赖。

## 2. 实施前约束

- 新一级项目名为 `project-commercial-advisor`；建立时同步更新工作区根目录 `repos.json`。
- 新项目拥有独立 Git 根目录和提交历史；不得在 `sat` 根目录初始化 Git。
- 未获得用户对第一阶段结果的确认前，不开始第二阶段。
- 不实现定时任务、爬虫、数据库、仪表盘或自动登录。
- 不使用样式章验证商业顾问。
- 不实现文本商业判断、体裁编辑、叙事补全或中文本地化。
- 不修改 Ruwen 的小说作者资料包、章节写作入口或现有作者上下文预算。
- 外部规则和数据在用户咨询时核验；平台资料只保存来源入口、口径提示和误判风险。

## 4. 第一阶段任务：独立商业顾问

### 任务 A1：创建独立仓库与最小插件骨架

实施动作：

1. 在 `sat/project-commercial-advisor` 建立独立目录和 Git 仓库；
2. 使用 `plugin-creator` 和 `skill-creator` 生成最小合法插件；
3. 插件只发布一个技能 `project-commercial-advisor`；
4. manifest 的描述强调项目立项与上线经营决策，不提章节写作或文本编辑；
5. 更新 `sat/repos.json`，记录新一级项目；
6. 添加 README，写明能力边界、首版平台和非目标。

测试先行：

- `tests/test_package_structure.py` 检查 manifest、技能目录、frontmatter、引用路径和 UTF-8 文件可读性；
- 检查包内不存在指向 `v5ruwen` 或工作区根目录运行代码的路径；
- 检查插件在未安装 Ruwen 时仍能独立加载。

验收：

- 新仓库可单独复制并通过结构测试；
- `repos.json` 已同步；
- 没有引入数据库、服务或网络常驻进程。

建议提交：`feat: scaffold project commercial advisor`

### 任务 A2：实现三阶段商业决策协议

在 `SKILL.md` 中实现三个同层级阶段：

1. 明确当前待作出的经营决策；
2. 建立或检验商业判断；
3. 提出立项、继续、调整、追加投入、降低投入、暂停或停止等行动。

必须写入的行为不变量：

- 没有具体经营决策时，不生成泛化商业报告；
- 根据问题自由选择证据，不输出固定分析维度或综合评分；
- 立项前形成可验证假设，上线后回到原假设检验；
- 明确区分事实、派生计算、解释、假设和情景估算；
- 用户保留所有投入和停止决定；
- 遇到文本阅读判断时，说明职责边界并转交独立文本能力；
- 商业顾问不直接修改项目设定、故事或正文。

技能只引用真正需要展开的两份参考资料，避免把正文写成特性清单。

验收：

- 立项问题和上线经营问题使用同一决策过程；
- 输入只有章节文本时不会伪装成商业立项或经营分析；
- 输出长度和结构随问题变化，但证据性质与不确定性始终可识别。

建议提交：`feat: define commercial decision workflow`

### 任务 A3：建立证据、数据和利润规则

在 `references/evidence-and-modeling.md` 中集中定义：

- 公开事实、公开观察、私有事实、派生计算、模型参数和商业解释；
- 缺失值不等于零、代理指标不等于经营结果、跨口径数据不得直接比较；
- 月票、推荐票和排名不能代替订阅、留存或收入；
- 实际现金收入、情景订阅收入和经济利润的边界；
- 未知参数使用变量或区间，不补造精确值；
- 来源、时间、单位、适用范围和限制的最小记录要求；
- 私有数据只在用户主动提供和授权范围内使用。

该参考资料规定推理底线，不规定固定报告字段。

验收：

- 公开代理数据无法导出虚构后台指标；
- 实际值、计算值和模型值不会混写；
- 缺少关键数据时能够给出最小下一证据，而不是填零。

建议提交：`feat: add evidence and modeling rules`

### 任务 A4：建立起点轻量平台资料

在 `references/platforms/qidian.md` 中只保存：

- 起点官方规则、帮助中心和公开作品页的核验入口；
- 咨询时需要检查的指标定义、活动期和统计周期；
- 公开页面可能出现的字数、章节数、更新时间、月票、推荐票和排名等字段；
- 用户后台可能提供的订阅、阅读、结算和收入数据类别；
- 订阅计价与利润模型所需参数的官方核验入口；
- 数据来源、自动访问和个人信息的合规边界；
- 最近核验日期的语义：只代表上次检查，不保证当前有效。

明确禁止：

- 写入会被误当作永久规则的当前阈值；
- 自动登录、账号凭证保存、私有接口访问和绕过限制；
- 建设全站作品快照或定时榜单历史。

验收：

- 删除网络连接后，平台资料仍不会声称旧规则是当前事实；
- 每次实际咨询都会先核验与问题有关的口径；
- 起点资料可以被其他平台资料替换，而不改变 `SKILL.md` 的三阶段流程。

建议提交：`feat: add qidian research adapter`

### 任务 A5：实现确定性计算器

创建无数据库、无网络访问的 `scripts/commercial_metrics.py`，只负责可复现计算，不负责商业解释。

提供两个子命令：

```text
commercial_metrics.py chapters --input chapters.json
commercial_metrics.py profit --input profit.json
```

`chapters` 输入每章标识、发布时间、字符数和可选的免费/VIP标记，输出：

- 有效章节数与缺失记录数；
- 总字符数；
- 平均数和中位数；
- 最小值和最大值；
- 首末发布时间；
- 可计算时的平均更新间隔；
- 按日和按周的章节数与字符数。

`profit` 支持两种模式：

- `actual`：使用用户提供的真实收入、扣减和成本；
- `scenario`：使用付费字数、假设付费人数、千字价格、分成和成本生成情景结果。

实现约束：

- 金额使用 `Decimal`；
- 时间必须带时区或明确来源时区；
- 缺失字段保持缺失，不自动填零；
- 负字符数、负人数、无效分成和重复章节标识必须拒绝；
- 单章数据的更新间隔输出 `null`；
- 输出 JSON 明确标记 `actual`、`derived` 或 `modeled`；
- 不保存输入文件，不建立缓存。

测试用例：

1. 未排序章节可得到正确时间顺序和间隔；
2. 单章、空数据和部分缺失数据行为明确；
3. 重复章节、负数和无效时区被拒绝；
4. 平均数、中位数、日更和周更计算正确；
5. 实际收入与模型收入使用不同标签；
6. 未知成本不被当成零；
7. 保守、基准、乐观情景按输入单独计算，不暗中调整参数；
8. 金额计算不存在二进制浮点误差。

测试命令：

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

建议提交：`feat: add deterministic commercial metrics`

### 任务 A6：建立轻量商业状态模板

`assets/commercial-state-template.md` 只包含：

- 当前经营决策；
- 仍有效的关键商业假设；
- 已被削弱或否定的假设；
- 用户批准的投入与风险边界；
- 当前需要验证的问题；
- 最近决策日期。

更新规则：

- 只有用户批准的经营决定才能改变当前决策和投入边界；
- 顾问可以提出变更预览，但不能自行提交；
- 市场研究原文、竞品材料、长篇推理和全量后台数据不得复制进状态文件；
- 旧假设的真值变化应保留简短结果，避免事后改写最初判断。

验收：

- 文件能够连接立项判断与上线复盘；
- 文件不演化为数据库、研究报告或写作规则；
- 不依赖 Ruwen 目录也能使用。

建议提交：`feat: add commercial state contract`

### 任务 A7：行为验证

建立 `validation/behavior-protocol.md`，使用同一模拟项目进行四项测试：

1. **立项测试**：只有构想、目标市场和资源约束；
2. **上线测试**：在同一项目中加入后台经营数据，要求检验原判断；
3. **代理指标测试**：只提供月票、排名等公开数据，要求估算订阅和收入；
4. **越界测试**：只提供一段合成小说文本，要求判断是否具有阅读吸引力。

通过条件：

- 立项测试形成可验证商业假设，而非模板化评分；
- 上线测试明确比较原假设与真实结果；
- 代理指标测试拒绝伪造订阅或收入；
- 越界测试说明文本判断不属于该技能；
- 所有数值来源、时间、口径和不确定性可复核；
- 顾问最终落到项目经营选择，不越权修改作品。

将实际运行结果和人工判定记录于 `validation/behavior-results.md`。未通过时优先精简或修正决策不变量，不增加更多角色和固定输出字段。

建议提交：`test: validate commercial advisor behavior`

### 第一阶段完成门

只有同时满足以下条件才向用户申请进入第二阶段：

- 全部自动化测试通过；
- 四项行为验证通过并获得用户确认；
- 独立技能不依赖 Ruwen；
- 没有常驻服务、定时采集或数据库；
- 起点规则在咨询时更新，而不是被永久固化；
- 立项和上线经营能够在同一项目状态中闭环。

- 样式章商业价值阅读测试；

