# Ruwen 项目阅读器与批注批次设计规格

状态：已通过视觉方向确认，等待书面规格复核
日期：2026-09-04

## 1. 目标

为 Ruwen 项目提供一个永久、可重复使用的本地阅读与批注模块。它读取现有项目目录，不复制或替代项目正典；以书名为项目最高识别对象，帮助使用者在一个连续工作流中完成文件浏览、阅读、版本比较、批注记录、批次封存与后续 Ruwen 处理交接。

模块不依赖 AI 才能运行。文件管理、Markdown 阅读、搜索、版本比较、批注录入、批次管理和本地校验全部离线完成。AI 只在封存批次被交给新的 Ruwen 任务之后参与解释、综合和修改决策。

## 2. 范围

### 2.1 第一版包含

- 打开任意符合 Ruwen 目录习惯的项目。
- 从真实目录生成文件树，不要求每个项目具有完全相同的文件数量。
- 阅读 Markdown、纯文本、JSON、JSONL 与 YAML 文件。
- 在阅读视图、源文视图和版本视图之间切换。
- 使用 Git 历史比较同一文件的版本；没有 Git 时仍可阅读当前文件。
- 对选中文段或结构位置写批注。
- 将多个文件上的多条批注归入当前草稿批次。
- 查看、编辑草稿批次；封存后保持不可变。
- 为封存批次生成独立的 Ruwen 处理包，供一个新任务统一处理。
- 在本地持久保存批注、批次状态、锚点与处理任务关联信息。

### 2.2 第一版不包含

- 在阅读器中直接编辑或覆盖项目文档。
- 将“批准”机械转换成对原文的立即修改。
- 自动决定批注应该修改哪一份设定。
- 自动向正典写入 Ruwen 的处理结果。
- 云同步、多人协作、账号系统和权限管理。
- 小说章节创作或编辑器角色的替代实现。

## 3. 产品原则

### 3.1 项目文件仍是唯一正典

阅读器只读取项目文件。批注与批次属于治理层，不产生一套平行的“已修改文档”。所有正典变化仍通过 Ruwen 的既有治理、审批和维护流程完成。

### 3.2 批注是输入，不是修改命令

一条批注只记录使用者在某处提出的判断、要求或疑问。它不会直接作用于被批注文件。封存批次进入新的 Ruwen 任务后，Ruwen 根据批注、锚点、相关文件和项目治理规则决定它应转化为设定修改、创作、维护、校验或不处理。

### 3.3 批次是处理边界

批次编号在项目内单调递增且永不复用。例如第四轮录入十条跨文件批注，整体仍是“第 004 批”。草稿可编辑；封存后不可修改。对封存批次的修正进入下一批。

### 3.4 默认只读

第一版所有项目文档操作均为只读。应用唯一允许写入的位置是项目内部的 `.ruwen/` 运行目录，以及封存时生成的治理快照目录。任何正典文件改动都必须发生在 Ruwen 处理任务中。

## 4. 信息架构与界面

### 4.1 主结构

桌面宽度下使用三栏一底栏：

1. 左栏：项目文件树。
2. 中栏：当前文档阅读器。
3. 右栏：当前锚点与批注输入。
4. 底栏：当前批次的唯一状态摘要。

阅读、文件管理和批注不拆成独立页面。使用者在阅读某一文件时直接选择文字、输入批注并送入当前批次，避免在“资料目录—阅读—审批”之间来回切换。

### 4.2 左栏

- 左上只显示项目名和项目切换入口。
- 文件树忠实反映真实目录层级。
- 默认排除 `.git/`、`.ruwen/`、缓存、构建产物与二进制文件。
- 不显示无意义的文件数量、类型徽章和项目类型标签。
- 只有存在批注的文件显示细小批注数。
- 搜索结果仍保持文件路径上下文。

### 4.3 中栏

- 顶部只保留路径、阅读、源文和版本。
- 阅读视图强调文档标题、章节层级、正文行距和负空间。
- 源文视图忠实展示原始文本，不做格式重写。
- 版本视图列出可用 Git 修订，可选择两个版本进行逐行比较。
- 选择正文后，右栏锚点立即更新，但不自动创建批注。

### 4.4 右栏

- 顶部显示“写批注”和本文批注数量。
- 锚点显示标题链、结构位置和短引文。
- 一个常驻文本框承担当前批注输入。
- “发送至第 N 批”只保存批注，不改变原文。
- 下方按当前文件展示本批次已有批注，并允许在草稿阶段编辑。

### 4.5 底栏与批次抽屉

- 底栏只出现一次当前批次状态：编号、批注数、涉及文件数和状态。
- “查看”打开批次抽屉，按文件分组列出全部批注。
- “封存并交给 Ruwen”先执行完整性检查，再生成不可变快照。
- 抽屉保留既往批次的最小状态索引，但不把所有历史内容同时展开。

### 4.6 响应式规则

- 中等宽度隐藏右栏，批注入口转为文内选择后的侧滑面板。
- 小屏改为文件树、阅读器、批注区的纵向顺序，底部批次栏保持可见。
- 桌面阅读宽度控制在约 680–740 像素，避免正文随窗口无限拉宽。

## 5. 视觉规范

### 5.1 字体

- 项目名默认使用“站酷小薇体”。
- 项目名字体可在“站酷小薇体”“霞鹜文楷”“思源宋体”之间切换。
- 文件树、正文、批注和所有功能文字固定使用“思源宋体”。
- 特殊字体不进入正文选择器，避免页面成为字体样张。
- 字体文件随模块自托管，不依赖设备安装；同时保留字体许可证文件。

三款字体均使用开放授权版本。实现时记录准确版本号与来源，升级字体必须单独测试字形、行高和页面换行变化。

### 5.2 色彩

- 纸色：`#F4F2EC`。
- 墨色：`#2C2D29`。
- 次级文字：`#777872`。
- 极淡结构线：`rgba(44,45,41,.12)`。
- 唯一强调色：暗赭 `#745148`，只用于当前文件、批注锚点和主要批次动作。

### 5.3 形式

- 不使用卡片、阴影、大圆角、渐变和装饰性图形。
- 分隔线只在真实结构边界出现。
- 层级主要通过字号、字距、段前距与留白建立。
- 界面不模拟古籍外观；东方气质来自文字、排布、纸色与克制，而不是卷轴、印章或纹样。

## 6. 本地架构

### 6.1 交付边界

模块作为 `v5ruwen` 仓库内一个可独立复制、测试和运行的组件建设，建议位置：

`07-项目阅读器/ruwen-project-reader/`

组件不得依赖 `sat` 工作区根目录中的运行代码。它通过命令行接收项目路径，也可在启动后选择项目目录。

### 6.2 技术形态

- Python 本地服务负责项目扫描、文件读取、Git 历史、SQLite 和批次快照。
- 浏览器前端使用本地 HTML、CSS 与 JavaScript 模块，不依赖网络资源。
- 服务只绑定 `127.0.0.1`，使用随机可用端口和会话令牌。
- 字体、Markdown 渲染器和前端资源均随组件固定版本保存。
- 启动命令以项目路径为参数，并自动打开本地浏览器页面。

这一形态延续 Ruwen 现有 Python 工具链，同时避免把浏览器原型的临时服务器当成正式运行时。

### 6.3 文件访问边界

- 所有请求路径在读取前解析为绝对路径并验证仍位于选定项目根目录内。
- 拒绝路径穿越、符号链接逃逸和未允许的文件类型。
- 单文件设置合理大小上限；超限文件只显示说明，不直接载入浏览器。
- 默认不把项目正文发送到任何网络服务。

## 7. 数据模型

### 7.1 运行数据库

每个项目首次使用时创建：

`.ruwen/control.sqlite3`

核心表：

- `project_state`：项目标识、当前批次号、界面偏好和最后打开文件。
- `annotation_batches`：批次号、状态、创建时间、封存时间、处理任务标识。
- `annotations`：批注正文、文件相对路径、锚点、文件哈希、创建与更新时间。
- `dispatches`：封存快照路径、处理任务标识、派发时间和处理结果状态。

数据库只保存治理运行状态，不复制完整项目文件内容。

### 7.2 批注锚点

每条批注同时记录：

- 项目内相对路径。
- 批注创建时的文件内容哈希。
- 标题链。
- 选中文本前后文。
- 原始行范围。
- 选中文本本身。

重新打开文件时优先按哈希和精确文本定位；文件发生变化后再使用标题链与前后文尝试恢复。无法可靠定位时标记为“需要重新定位”，不得静默移动到近似位置。

### 7.3 批次状态

状态机：

`draft → sealed → dispatched → processing → completed → archived`

- `draft`：允许新增、编辑和删除批注。
- `sealed`：内容与顺序冻结，生成快照。
- `dispatched`：已经与一个 Ruwen 处理任务建立关联。
- `processing`：Ruwen 正在解释和处理。
- `completed`：处理任务已返回结论或变更成果。
- `archived`：处理结果与正典维护完成，保留审计记录。

封存失败时批次保持 `draft`，不分配下一个编号。

## 8. 封存快照与 Ruwen 交接

封存后生成：

`治理/批注/批次-0004.json`

快照包含：

- 项目标识与批次号。
- 批次内全部批注及稳定顺序。
- 每条批注的锚点和文件哈希。
- 涉及文件的相对路径与锁定版本标识。
- Ruwen 处理契约版本。
- 快照自身哈希。

新开的 Ruwen 任务只接收本批快照、涉及文件的锁定版本和必要治理规则，不自动携带其他批次、旧聊天、作者上下文或无关项目资料。任务先进行解释与归类，再决定需要调用的 Ruwen 能力；未经既有审批流程，不直接写入正典。

第一版的派发边界是生成完整处理包并提供“复制任务说明／打开处理位置”。与 Codex 桌面任务创建的自动连接作为独立适配层，不进入数据库核心和批次格式，避免绑定不稳定的界面接口。

## 9. 校验与失败处理

封存前检查：

- 批次至少有一条非空批注。
- 所有路径仍位于项目内且文件存在。
- 每条批注包含锚点与创建时文件哈希。
- 同一批次没有重复批注标识。
- 快照目标路径不存在；批次号没有被使用。

常见失败：

- 文件已变化：保留批注，但要求确认或重新定位后再封存。
- Git 不可用：版本页说明不可用，其他阅读功能继续工作。
- 数据库锁定：显示明确重试信息，不创建部分批次。
- 快照写入失败：事务回滚，批次仍为草稿。
- 字体资源缺失：启动自检报错，不静默回退成另一款字体。
- 项目路径不可访问：停止加载并提示重新选择，不展示部分目录。

## 10. 测试策略

### 10.1 单元测试

- 目录过滤、路径规范化和逃逸拒绝。
- 支持文件类型与大小限制。
- Markdown、JSON 和 JSONL 的安全展示。
- 锚点创建、精确恢复、模糊恢复和失效。
- SQLite 迁移、事务与批次状态转换。
- 批次编号单调递增且不可复用。
- 封存快照稳定排序与哈希一致性。

### 10.2 集成测试

- 在项目模板副本中完成“打开文件—选择文字—批注—封存”的完整流程。
- 使用有 Git 和无 Git 两类项目验证版本视图。
- 文件在批注后改变时验证重新定位提示。
- 服务重启后恢复当前批次、最后文件与字体偏好。
- 验证项目文件除指定治理快照外没有发生写入。

### 10.3 界面验证

- 桌面、中等宽度和小屏三档截图回归。
- 三款项目名字体的真实加载检查。
- 键盘完成文件导航、视图切换、批注发送和抽屉操作。
- 长文件名、深层目录、长批注和空状态不破坏布局。

## 11. 验收标准

第一版完成时应满足：

1. 可对任意 Ruwen 项目只读浏览，无需修改其目录结构。
2. 页面保持已批准的三栏阅读器、右侧批注与底部批次结构。
3. 字体真实自托管，项目名与正文字体规则符合本规格。
4. 批注可跨多个文件归入同一批次，并在重启后保留。
5. 封存批次不可编辑，编号不可复用，可生成可审计 JSON 快照。
6. 文档发生变化时，不会把旧批注静默附着到错误文本。
7. 不使用 AI 也能完成全部本地阅读与批次准备工作。
8. Ruwen 处理包不会自动改写项目正典，也不会泄漏无关上下文。
