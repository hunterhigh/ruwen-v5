# Ruwen Writing System · 如文写作系统

**面向长篇小说的结构化 AI 写作系统：从故事设计和项目知识，到隔离章节生产、审读校验与正典记忆维护。**

如文把长篇小说创作拆成职责明确、可以检查、可以恢复的工作环节。它不把“生成一段文字”误当成完整写作系统，而是同时处理故事构思、外部知识、项目声音、章节情境、隔离写作、多角色审读、用户批准与长期记忆维护。

## 系统组成

### 核心写作系统

主插件提供两个公开入口：

- **如文·故事构思**——初始化和扩展小说项目，接入外部知识与文学参考，设计人物和世界，并把已批准的创意编译为章节情境。
- **如文·章节写作**——根据已批准的章节情境在隔离上下文中写作，然后协调首次阅读、编辑、情节与现实核验、用户批准和正典记忆更新。

这种分离是有意设计的：规划记录、修正历史和校验器应当指导创作，但不应泄漏进小说正文。

## 开始使用

```bash

```

## 设计原则

- **上下文隔离。** Author 只接收已批准的创作情境，不接收完整规划和修正系统。
- **正典具有批准边界。** 草稿和分析只有经过用户批准，才能成为项目事实。
- **角色权限保持收敛。** Reader、Editor、Validator 和 Memory Maintainer 提供不同判断，而不是被折叠为一个不透明 Agent。
- **外部知识保持可追溯。** 研究与文学参考作为项目资源接入，而不是无声混入生成正文。
- **结论必须与证据匹配。** 结构验证可以证明软件包完整，但不能单独证明文学质量得到提升。

## 版本管理

仓库名称不再包含版本号。产品版本通过明确的版本材料管理：

- [`VERSION`](VERSION) 记录当前如文版本线。
- [`CHANGELOG.md`](CHANGELOG.md) 记录用户可感知的变化。
- Git 标签和 GitHub Releases 使用 `vMAJOR.MINOR.PATCH`。
- 可以独立演进的安装组件继续维护自己的 manifest 版本。

- 当前如文版本：**5.0.0**
- 当前成熟度：**Candidate**

核心软件包已经通过结构和自动化检查。文学质量仍然是项目层面的结果：项目声音或领域能力只有完成闭合审计、非正典试写和用户阅读后才会激活。
