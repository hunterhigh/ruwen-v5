# 网文体裁编辑器

## 目标

直接编辑 Author 已写完但尚未获得用户批准的网文初稿，使事件不仅发生，而且能被读者理解、估值、期待和回味。编辑后的全文仍是候选稿；本技能不加入 Author 的工作流，也不拥有正典写入权。

执行编辑前，完整读取：

- [编辑方法](references/editing-method.md)
- [上下文与批准边界](references/context-and-approval.md)

## 入口

只处理已经存在的正文初稿。若用户提供的是大纲、章节情境或零散构思，说明需要先由作者完成初稿，不代替 Author 写第一版。

开始前确认正文仍处于批准前状态。若它已经进入正典，只有在用户或项目所有者先将其重新开放为修订候选后才能编辑。

优先从用户给出的文件和项目中发现项目声音、锁定事件与相关事实。不要要求用户填写统一配置表；只有缺少的信息会让本次深度补写产生不同剧情结果时，才提出一个最小问题。

## 编辑过程

### 1. 保留 Author 原稿

实质修改前保留可恢复的 Author 版本。项目已有版本、快照或修订机制时沿用；没有时保存一份明确标记为 Author 原稿的副本。不得只留下改后稿。

### 2. 读成稿

先把正文当作普通读者连续读完，再判断本章实际缺少什么阅读效果。不要从“世界观、动机、伏笔”等通用栏目出发寻找可填空的位置。

允许结论是“不需要体裁扩写”。若正文已经成立，不得为了显示编辑价值而增加说明、回忆、旁观议论或设定材料。

### 3. 深度重织

围绕已经发生的剧情选择少量高价值位置，直接修改完整正文。可以补充、扩写、删减、移动、改写段落，也可以调整扩写点前后的动作、判断和对话，使新内容具有入口、内部运动和回流。

新增讲述必须服从项目声音和限定视角。它可以直白、评论性强或暂时离开眼前，但需要一直受当前欲望、危险、关系、胜负或后果牵引。说明本身也要有叙事性，不能写成批注、规则解释或百科条目。

可以在重织过程中清理翻译腔、语序和不自然的中文表达，但不得把深度编辑退化成全篇同义词润色。

### 4. 复核与交还

完成后连续阅读改后全文，检查：

- 新内容是否改变了理解、估值、情绪、预期或后果；
- 前后文是否因扩写产生重复、断裂或节奏失衡；
- 讲述声音是否仍属于本书；
- 是否改变了锁定事件、人物选择、世界规则或结果；
- 是否把尚未批准的补充误写入正典资料。

主要交付完整改后候选稿，并附一份简短改动说明。说明只标出深度补写区域、产生的阅读作用和可能需要上游确认的问题，不把编辑批注混进正文。

## 越界处理

如果需要新增或改变世界规则、人物长期动机、关系正典、事件顺序、胜负结果或未来剧情前提才能使章节成立，停止相应改写，指出必须返回构思的问题。不要为了完成编辑而补造答案。

修改后的正文仍由原项目的阅读、核验和用户批准机制处理。用户批准前，不更新正式章节、人物、世界、故事、连续性或记忆。
